# Локальная проверка — 19 октября 2026

Проект создан в исходно пустой рабочей папке. Git-репозитория и существующих пользовательских изменений не было.

- Python: 3.13.2, Windows.
- Зависимости: discord.py 2.7.1, python-telegram-bot 22.8, aiohttp 3.14.5.
- `python -m unittest discover -v`: **69 тестов, OK**. В том числе обе стороны моста, дубли, фильтры, ответы, редактирование/удаление, файлы, фото, лимиты, временные и неопределённые ошибки, восстановление SQLite, подтверждение Telegram updates только после записи, права, логи и запуск PowerShell.
- `ruff check bridge tests`: пройдено.
- `ruff format --check bridge tests`: пройдено.
- `python -m compileall -q bridge tests`: пройдено.
- `python -m pip check`: несовместимых зависимостей не найдено.
- PowerShell AST-проверка обоих скриптов: ошибок синтаксиса нет. `start.ps1 -NonInteractive` проверен без токенов: безопасно завершается кодом 2 до подключения.
- `python -m build --no-isolation`: wheel и sdist собраны в `dist/`.

Тесты API используют моки. Настоящие подключения к Discord/Telegram, отправка в реальные чаты, доступность конкретного webhook и публичных аватаров **не проверялись**. Настоящих токенов/ID не предоставлено, аккаунты ботов не создавались.

Для реальной приёмки нужны `DISCORD_TOKEN`, `TELEGRAM_TOKEN`, `DISCORD_WEBHOOK_COMMUNITY`, Discord channel ID и Telegram group ID. Создание и настройка описаны в README.md. Токены в чат присылать не нужно.

Особенности среды проверки: Windows asyncio использует внутренний loopback socketpair, поэтому тесты выполнялись вне сетевой песочницы с разрешением. Сборка также выполнялась с разрешением из-за ограничений доступа к временному файлу сборщика. Внешние API ботов при этом не вызывались. Библиотека Telegram выдаёт уведомление о будущей смене типа `retry_after`; код поддерживает как число секунд, так и `timedelta`.
